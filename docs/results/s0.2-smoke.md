# S0.2 vendor smoke

Run on 24 Nov 2026. No secret values are in this report. Estimated Groq cost about $0.0005. Rumik `credits_used` on every `done` frame was 0, so the character rate is still unknown.

## Groq

`GET /openai/v1/models` returned the eleven ids already listed in the plan. All seven required ids were present.

Instruct versus thinking, from https://console.groq.com/docs/reasoning and confirmed by the calls:

- Qwen 3.8: `reasoning_effort=none` is instruct mode. It returned `ok` with no reasoning field. `default` also returns no reasoning tokens on Groq. `low`, `medium`, and `high` turn reasoning on.
- gpt-oss 20B and 120B: `reasoning_effort` is `low`, `medium`, or `high`. `none` is not supported. With `low`, the reply was `ok` and a `reasoning` field was present (`reasoning_tokens` 8 on 20B, 16 on 120B). `reasoning_format` is not supported on these models. `include_reasoning` can hide the reasoning field.

Strict JSON schema on `qwen/qwen3.8-27b` with `reasoning_effort=none` was accepted. For a narration that only said "I bought a phone", the model returned `order_id` with `certainty=not_stated` and `value=""`.

Prompt Guard 2 86M returns a probability string, not a label. English and Hindi benign sentences scored about 0.0004. The two "ignore your instructions" sentences scored about 0.999. A threshold is still to be chosen in S5.4.

`openai/gpt-oss-safeguard-20b` with `reasoning_effort=low` and a short mandate policy returned JSON: violation true, category `settlement`, for a sentence that accepted a partial refund.

Whisper `whisper-large-v3-turbo`, `response_format=verbose_json`, `language=en`, on a 4.3 second synthetic clip. Billed minimum is 10 seconds. Segment fields: `id`, `seek`, `start`, `end`, `text`, `tokens`, `temperature`, `avg_logprob`, `compression_ratio`, `no_speech_prob`. The clip said "twelve hundred rupees"; the transcript was "The refund of Rs 1,200 is still pending."

## Rumik

Base URL used: `https://silk-api.rumik.ai`.

`GET /v1/voices`: `muga` languages are hinglish and english, no named voices, default model. `mulberry` languages are english, hinglish, and hindi, with named voices Emma, Mia, Sophia, Ava, Lucas, Noah, Theo, Adam, and speaker_1 to speaker_4.

`GET /v1/agent/limits`: `concurrency_limit` 4, `plan` payg, `active_requests` 0. The payload has no credit balance, price, or expiry.

`POST /v1/tts/ws-connect` requires `text` in the body (`VALIDATION_ERROR` if it is missing). The streaming doc says the mint does not judge the text; the field is still required. `expires_in` was 300. The websocket token was not stored.

Time to first audio chunk after the socket send, one short sentence:

| Clip | First audio |
|---|---|
| mulberry hinglish | 303 ms |
| mulberry hindi | 297 ms |
| muga hinglish | 285 ms |
| muga hindi | 275 ms |

`muga` has no hindi entry in the voices catalog, and the API still accepted `language=hindi` and returned audio. WAVs are in `docs/results/s0.2-audio/`. A person still has to pick the voice by ear.

A second text frame on an open mulberry session returned `cancelled` with `reason=interrupt`, then `done` for the new line, and that line produced audio. An explicit `{"type":"cancel"}` returned `cancelled` with `reason=cancel`. `muga` also emitted a `queued` frame before `done`.
