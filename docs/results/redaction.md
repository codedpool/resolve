Engine: `server/app/privacy/redact.py` with the number normaliser in `numbers.py`. Set: 150 labelled strings in `workflows/evals/datasets/redaction.json`, regenerated by `workflows/evals/build_redaction_set.py`. Score script: `server/scripts/eval_redaction.py`.

Order-id tokens round-trip on all 15 strings, and the same id reuses its token. A detector error withholds the whole segment. Nothing in the engine logs a string.

## How far to trust the numbers

I wrote the set and the engine together, so a perfect score on it is weak evidence. A held-out probe of fourteen new strings found six gaps, which are now fixed and added as tests: UPI handles without a domain suffix, passport numbers, bank account numbers, a bare pin code after an address, a house number before a street name, and spaced single digits in a code. The set needs strings written by someone else, with real transcripts, before the numbers mean much. Address recall in particular is only meaningful on real addresses. Until then, treat zero leaks here as "the rules do what they say", not as a measured recall.

Additions beyond the plan's class table: phone numbers, email addresses and UPI handles are redacted irreversibly, because they are plainly personal data.
